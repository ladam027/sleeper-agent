How to get the most out of Sleeper Agent

Short version: leave chat on Auto, pin your core facts, and let the budgets do their job.

1. Teach it who you are (once)

Tell it your name, job, city, goals, projects and preferences in one message. Then go to Memory and pin the 5–10 facts it needs constantly. A single "Owner profile" memory works best. Pinned facts ride along with every message for about $0.00004 each and save a paid search on every question.

2. Leave chat on Auto

Auto sends each message to the agent that handles it: quick questions and everyday dashboard updates to Pete (Haiku), website work to Mia, planning, research and anything complex to James (Opus), who brings in Riley or Cleo when needed. If an agent can't do something, it's handed on automatically; you never get "ask someone else". Each reply shows who answered and what it cost.

3. One conversation, many models

In Auto, both agents share one conversation, so the orchestrator sees what you told Quick and the other way round. Pick an agent by name only to force it. History is capped at the last 20 messages to keep costs flat, and anything older lives in memory.

Model prices

Per million tokens. A typical short chat turn is 2–6k tokens in, 100–500 out.

"Cached" is the price when the same prompt prefix was sent in the last 5 minutes. Back-to-back messages are much cheaper than spread-out ones.

Keeping costs to a minimum

  • Batch your asks. One message with three requests beats three messages, because each turn re-sends the conversation.
  • Be specific. "Draft 3 Etsy titles for a minimalist fox print" is cheaper than a vague ask plus two rounds of clarification.
  • Chats compress themselves. Only the last few messages (Settings) are sent with each request. Older ones are folded into lasting memories plus a short summary you can read at the top of the chat.
  • Pin carefully. Pin stable facts only. Editing a pinned memory resets the cache, so the next message costs a bit more.
  • Check Statistics. It shows spend per agent over today, 7 days, 30 days or all time, what the money paid for, and tips worked out from your own usage, most with a one-click fix.
  • Budgets are hard stops, with an override. Each agent has a daily cap and there's an overall cap in Settings. When one is hit, the task pauses and you get an approval request (dashboard or Telegram, Y 12 PIN). Approving raises that limit for today only and the task continues. One request per limit per day; after a "no" it won't ask again until tomorrow. You can also press Raise limit on an agent card. A runaway loop is still cut off after 8 steps.
  • Phrases that stay cheap on Auto: questions, lookups, "remember that…", quick edits.
  • Phrases that go to James (Opus): plan, research, analyze, build, draft, compare, strategy, business, invest, marketing, website, latest/news/price/search, critique, or anything over ~500 characters.
  • Force a model any time with the picker above the chat.

Agent settings

Overview → Agents → Settings on any agent card

Effort (Opus only)

How hard the model thinks before answering. Thinking is billed as output at $20/M on Opus, so this is the biggest cost dial. Low for routine work and chatting. Medium (default) for most tasks. High only for plans or decisions where a better answer is worth paying for. Simple questions go to Haiku on Auto anyway, and it doesn't think.

Reply style

Ultra concise (James and Pete by default): 3–4 sentences, just the answer and anything you need to do, never a list of what the agent fixed or checked behind the scenes. Concise: answer first, deliverables complete without filler. Full: for agents whose job is long writing. Any style still gives a full draft or plan when you ask for one.

Max reply length

A hard ceiling on output per step, so a rambling reply can't run up the bill. On Opus it includes thinking, so keep it at 8k or more. If a reply is cut off, it says so and tells you which setting to raise. 1k is plenty for Quick.

Settings apply from the next message. Check the effect on the Costs tab after a day or two.

Memory vs Vault

Ask yourself: does the agent need to know it, or only use it?

  • Memory (agent reads it, and it's sent to Anthropic): name, job, city, birth year, goals, projects, allergies, which bank or broker you use.
  • Vault (encrypted, never sent): anything that would let someone log in as you, pay as you, or steal your identity.
  • Don't vault what the agent should know. Every vault value is swapped for {{secret:name}} before sending, even inside memory. Vault "Logan Adams" and your name disappears from everything the agent sees.
  • Card numbers and SSNs are stripped from chat automatically, even if you never saved them.

Safety controls

  • Approvals: risky actions (creating agents now; sending, posting, paying and trading later) wait on the Overview until you approve them.
  • Kill stops one agent mid-task. Restart clears a stuck one. The red Kill switch blocks every agent from calling the API.
  • The dashboard only listens on this computer. Phone access comes in Build 2 via Tailscale.
  • Your chats, memory and vault live in data/agent.db. Updates never replace it, and it's backed up on every start.

Reminders & alarms

"Remind me to call mom at 5" (dashboard), "message me at 9 to submit the form" (Telegram), "wake me at 6:30 on weekdays" (a phone call from your Telnyx number, which rings even in quiet hours because you asked). Times follow your timezone, including DST and travel.

  • When agents reach you: low = dashboard only. High = Telegram. Critical = phone call + Telegram, only for urgent things. During quiet hours, calls become messages.
  • At your desk, no texts: while you're actively using the dashboard (tab open, typed or clicked in the last 2 minutes), alerts and approvals pop up on screen instead of going to Telegram. If you messaged the bot in the last 15 minutes, you're "on your phone" and updates go to Telegram. Reminders you set and urgent calls always go out as you chose.
  • Cost: Telegram is free. Calls are about 1¢ each (Telnyx), counted in the Costs tab. Caps of 100 messages and 5 calls a day stop runaway loops.
  • Calling James by phone, and James calling other people, come in Build 7 (voice agent).

How the vault is protected

Encryption

Each item is locked with AES-256-GCM. The 256-bit key is derived from your passphrase (scrypt, deliberately slow to guess) and exists only in the server's memory after you unlock. It's never written to disk. Each save uses a fresh random nonce, and a tamper-check tag means altered data fails to open. Only each item's name and type are stored in the clear, so agents can list them.

Locked vs unlocked

The vault locks when the server restarts (including after updates), after an hour in which no key was used, or when you press Lock vault. Each time an agent uses a key (Canvas, Kalshi, Netlify…), the hour restarts. While locked, card numbers and SSNs are still stripped from chat, but your saved values aren't, and integrations pause until you unlock. Viewing or editing items needs your passphrase again after an idle hour. Forget the passphrase and the vault can't be recovered.

Who can see what

Your agents: names only, never values. Anthropic: never receives vault values. Claude Code (the assistant that builds this app) and anything else with file access: nothing on disk can decrypt the vault, and the dashboard token in .env can't view or change items. That takes your passphrase. Use your own browser (Safari/Chrome) for the vault, not the in-app preview pane.
